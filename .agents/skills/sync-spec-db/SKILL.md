# 仕様・DB資料の同期

このリポジトリ専用の手順。仕様とDB資料を現在の実装へ統合し、未実装計画・変更案・レビュー待ちを区別して残す。常設ルールは[AGENTS.md](../../../AGENTS.md)を読み、そこへ重複する規則を増やさない。

## 対象と基準を固定する

プロジェクトルートで現在のブランチ・未コミット差分・関連ファイルを確認する。合意した対象IDと今回変更する資料を特定し、並行する変更を保持する。

参照する正本は次の3冊。現在の版・テーブル数・列数・完了状態をスキルへ固定しない。

- [要求仕様書](../../../docs/要求仕様書.md)：合意範囲・本文・受入条件。
- [ER図とデータ設計](../../../docs/ER図とデータ設計.md)：現行の構造・物理ER・項目・制約と将来案の区分。
- [仕様管理](../../../docs/仕様管理.md)：対象IDの状態・検証・ユーザーレビュー。

資料を編集する前に、現在の作業ツリーのIDを保存する。HEADだけを基準にすると未コミットの新規IDを見落とす。

```sh
task_doc_ids=$(mktemp /tmp/invoice-doc-ids.XXXXXX)
python3 .agents/skills/sync-spec-db/scripts/check_docs.py --snapshot-ids > "$task_doc_ids"
```

同じシェルを使わない場合は、作成した一時ファイルの絶対パスを後の照合へ渡す。ファイルに含むのは仕様・管理表のIDだけである。

## 差異の根拠を判断する

対象のコード・マイグレーション・テストを、合意済み本文と照合する。後から承認された変更があれば現行本文へ統合する。仕様にない実装、不足したテスト、承認の根拠がない変更を見つけたら、不一致を示す。コードに合わせて要求を変更したり、この資料作業で機能を追加したりしない。

コード反映・検証完了・レビュー完了を読み分ける。作業中の変更案や部分実装は区分を明示し、管理状態を推測で進めない。並行作業で対象が変わった場合は、その差分を確認してから編集する。

## 正本を更新し、補助表示を揃える

古い本文・図・項目定義を現行へ置き換える。履歴の追記だけで済ませず、実装前の案を現行の図へ混ぜない。節番号・固定ID・受入条件を保持し、本文や受入条件を管理表へコピーしない。

関連するREADME・技術構成・業務フロー・移行復元手順等だけを更新する。旧版の移行手順は保ち、実データや実行環境固有の値を資料へ転記しない。DB構造の照合には下のスクリプトを使い、ローカルの稼働中DBを開かない。

DB資料を変更した場合は、正本に記載された生成方法に従う。現在のER補助表示の生成コマンドは次のとおり。既存の生成スクリプトを使い、HTML・SVGを独立した仕様として編集しない。

```sh
python3 docs/diagrams/build-er-viewer.py
```

## 照合し、結果を記録する

```sh
python3 .agents/skills/sync-spec-db/scripts/check_docs.py --baseline-ids "$task_doc_ids"
git diff --check
```

照合スクリプトはPython標準ライブラリだけを使う。マイグレーションと資料のDDLを別々のメモリDBへ適用し、版・テーブル・列・型・NULL・既定値・PK/FK・CHECK・一意制約・索引を比較する。現行Mermaidの項目・キー・関連と多重度、項目表、閲覧HTML、IDの一意性と保持、主要資料のローカルリンク先の存在も確認する。ファイルDBのATTACH・VACUUM INTOは拒否し、入力資料・実DB・生成物を書き換えない。

機械検査の成功だけで完了としない。対象IDごとの仕様・受入条件・コード・テストの意味の一致、承認・レビューの根拠、現行と計画の区分、図・閲覧画面の表示を人が判断する。リンク先の節や説明の意味、SVGの表示はスクリプトの検査対象外である。

図を再生成した場合は表示と再生成時の差分を確認する。アプリの検証は変更範囲とプロジェクト指示に応じて実行し、文書のみの変更で不要な業務テストを追加しない。失敗時に資料・制約・テストを弱めて検査を通さない。未対応の資料形式は検査成功と扱わず、根拠を確認して検査側を更新・検証する。

[設計の決定記録](../../../docs/design-decisions.md)へ、対象・確認日・検証結果・未確認事項を記録する。完了報告では更新した正本と表示用資料を示し、残る不一致・失敗・レビュー待ちを明示する。スキルの実行をコミットや受入完了の承認とみなさない。

補助スクリプト自体を変更したときは、架空資料による回帰検証を行う。

```sh
python3 .agents/skills/sync-spec-db/scripts/test_check_docs.py
```
