# JSONファイルのバックアップと復元

版：0.12 バックアップリストと履歴の保持　更新日：2026年11月22日

要求と受入条件の正本は[要求仕様書](要求仕様書.md)§24、状態は[仕様管理](仕様管理.md)S20。本書は内部形式・保存・復元の補助資料。ユーザーがPCのGoogle Drive同期フォルダを選ぶ方式を承認し、旧タブ保存とツール内のGoogle接続をファイル保存へ置き換えた。本番レビュー・別PC実機・Drive同期は未確認。

専用画面は`/backup.html`。上段に「バックアップ保存」と「復元」を横並びで配置し、その下に「バックアップリスト」を表示する。リストは保存日時・場所・含まれるデータを新しい順に並べる。390px幅では保存・復元とリストを縦並びにする。月次からの未保存の移動は保存・破棄・中止を確認し、失敗時は元画面と入力を保持する。URLで引き継いだ年月を月次への戻り先、同じ年を年間への戻り先に使う。処理中はナビを無効にし、ページ離脱・再読込を確認する。

## 1. 保存対象と形式

現行の[DB定義](ER図とデータ設計.md)にある全5表・46列・行順を対象とする。JSONは形式バージョン1のmanifest（形式名・スキーマバージョン・ID・データ取得日時・件数・SHA-256照合値）とbody（項目定義と各表の全行）を持つ。INTEGERは10進文字列、TEXTは文字列、NULLはnullとし、大きな整数・小数表記・改行・絵文字を保持する。DBスキーマはバージョン9。認証設定・トークン・PC内のパス・最新保存記録は業務バックアップへ含めない。

新規ファイル名は「請求管理ツール_バックアップ_YYYYMMDDHHMMSS_識別子.json」。日時は日本時間、識別子はバックアップIDの先頭8文字。既存の同名ファイルを上書きしない。20MiBを上限とし、超過時は切り捨てず処理を中止する。

## 2. 書出しと保存

1. ボタン操作直後にshowDirectoryPickerを開き、利用者が保存先フォルダを選ぶ。Google Driveへ保存するときはPCの同期フォルダを選ぶ。
2. 全業務データの整合したスナップショットを読取トランザクションで固定する。一時DBへ復元して全件一致を確認しJSONとして返す。
3. 選んだフォルダ内に新規ファイルを作り、書込み・終了後に読戻してJSON文字列の一致を確認する。取消・失敗で成功表示と最新記録を更新しない。
4. 保存確認後にデータ取得日時・保存日時・フォルダ名とファイル名・全件数を端末内へ記録する。ブラウザはフルパスを返さないため、フォルダ名とファイル名だけを保存場所として表示する。

フォルダ選択APIに未対応の環境ではBlobの通常ダウンロードを使う。開始日時と「ブラウザのダウンロード先（フォルダ未確認）」を記録し、保存完了を断定しない。ダウンロードしたJSONを同期フォルダへ移す案内を出す。PC用Google Driveアプリの導入・ログイン・同期状態は利用者が管理する。ツールはDrive同期完了を検知・保証しない。APIの説明は[File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)を参照する。

## 3. バックアップリストの記録

DBと同じディレクトリのbackup-state/recordsへ、1件ずつ「記録ID.json」として保存する。保存日時・取得日時・フォルダ名／ファイル名・保存方法・全表の件数と、並び順を保つ内部ID・通し番号を持つ。ディレクトリ700・ファイル600で所有者だけが読めるようにし、一時ファイルから置き換える。通し番号の降順で新しい記録を先に表示する。件数による切り捨てや自動削除はしない。

以前のbackup-state/latest.jsonから最新1件を引き継ぎ、新しい保存結果を記録する時に履歴へ保存する。旧ファイルは変更・削除しない。元の内容から作る固定IDで再起動時の重複を防ぐ。新しい記録IDはバックアップIDを使い、同じ保存結果の再送を重複登録しない。履歴の書込みに失敗した場合は、既存の履歴を保持する。

起動時に履歴を検証し、壊れたファイルは変更せず警告する。正常な行と新規保存・通常業務は利用できる。記録は保存結果の履歴であり、選択フォルダを自動走査したファイル一覧ではない。過去に保持していなかった履歴は復元せず、ファイルを移動・削除してもリストは変えない。認証設定・本人のトークン・フルパスは記録しない。履歴自体は業務バックアップに含めない。

## 4. ファイル選択からの復元

1. 利用者が20MiB以下のバックアップJSONを選ぶ。選択変更で古い確認を破棄する。
2. 形式・バージョン・全列・型・件数・照合値とID・関連を検証する。マイグレーションから一時DBを構築して全件復元し、全列・行順の一致を確認する。外部URLやファイル内のSQLは実行しない。
3. データ取得日時と件数を表示する。確認は10分間・1回限りで、確認後にDBが変更された場合は拒否する。利用者が復元を明示的に実行する。
4. 現在DBをrestore-backupsへ所有者専用ファイルとして退避し、整合性と全件一致を確認する。その後にトランザクションで全件を入れ替え、コミット前に全表全列・行順を再照合する。不一致やDBエラーは全件ロールバックする。
5. 復元世代をbackup-state/database-generation.jsonへ先に記録し、再起動後も旧画面からの保存を拒否する。旧配置google-backup/database-generation.jsonは世代だけを読み継ぐ。旧Google設定とトークンは読み込まず、削除もしない。

月次の未保存入力を保存または明示的に破棄してから専用画面へ移る。移動中止と保存失敗では入力と対象年月を保持する。復元失敗で元DBを保持した場合も、世代確認のため古い画面は再読込が必要になることがある。元の金額と条件を保持し、差分マージや手編集ファイルの取込は行わない。

## 5. Google連携の取扱いと未確認範囲

ツールはGoogle設定JSON・ログイン・Drive／Sheets APIを必要としない。旧Google関連の単体モジュールと回帰検証は保持するが、現行API・画面から呼び出さない。旧Google設定とトークン・既存スプレッドシートは変更しない。自動バックアップ・頻度・世代数・削除は追加しない。本番画面レビュー・実際のDrive同期・別PC実機の結果は仕様管理で区別する。
