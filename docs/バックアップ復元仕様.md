# スプレッドシートへのバックアップと復元

版：0.9 Google Pickerとdrive.fileによるファイル単位の認可を反映（架空DBによる実通信検証済み・本番レビュー待ち）　更新日：2026年11月15日

本書はS20の内部形式・接続・復元手順の補助資料。OAuthクライアントと設定JSONは、ユーザーの操作時承認を得て作成・保存済み。Sheets・Drive・Picker APIの有効化と本人のテストユーザー登録を確認した。架空DB専用アプリで本人の認可と指定ファイルの選択が成立し、実APIで保存・読戻し・別DB復元の全件一致、既存2タブの保持、再起動相当の接続読込み・トークン更新、未選択ファイルへのアクセス拒否を確認した。画面から変更済みの架空DBを退避・復元し、全件一致・退避保持・選択先差替えの403拒否・旧画面からの保存の409拒否も確認した。本番ユーザーレビュー・他PC実機での検証は未完了。要求の正本は[要求仕様書](要求仕様書.md)§24、状態は[仕様管理](仕様管理.md)。

日常の正本はローカルDBとし、利用者が指定したGoogleスプレッドシート内の専用タブへ管理データを書き出し、そこから復元する。参考表を保存先として明示指定した場合も、元からあるタブは編集せず、新しいバックアップタブだけを変更対象にする。具体的な保存先URLや認証情報はGitへ記録しない。

## 0. 実データで使い始める前に完成させる

MVP 1の画面レビューは架空データで行う。MVPの段階に関係なく、実データの利用開始前にバックアップと復元の実装・検証を完了する。

現行の物理DBは版9の5表・46列で、会社・年月ごとの表示設定も含む。構造の正本は[ER図とデータ設計](ER図とデータ設計.md)。将来の論理案は未実装部分を含む。途中段階では、その時点で実装済みの業務テーブル・項目と設定をすべて保存・復元し、スキーマ版と対象一覧を明示する。未実装テーブルをバックアップのためだけに作らない。後続段階でデータ構造が増えたら、書出し・復元・移行と検証も同じ変更で更新する。

## 1. 対象データ

S20着手時点の[現行DB](ER図とデータ設計.md)に存在する全表・全列を対象とする。以下は将来範囲を含む一覧で、未実装の表・項目・設定をバックアップのためだけに追加しない。

| 対象 | 保存する内容 |
|---|---|
| 取引先・月別表示 | ID、名称、会社・年月ごとの表示設定（S31）。メモ・表示順は採用・実装後に含める。S18の長期未取引先の判定・全期間共通の非表示は対象外 |
| 報酬条件 | 単価、税込／税抜、値引き・源泉条件、適用期間 |
| 請求対象 | 内容、小数時間、対象年月、単価、金額、条件と切替前の値。S25の日別稼働・分入力は対象外 |
| 月次請求・請求明細 | 会社×月、明細の源泉有無、合計、MFで計算した源泉の手入力額、請求済・入金済・MF消し込み済 |
| 国保・年金 | 種類、対象年月、支払額、メモ |
| 業務設定 | 復元に必要な設定と形式の版 |

添付・PDF・ファイル参照・添付情報・操作履歴台帳は扱わない。認証情報、トークン、端末固有のパス等は保存しない。

## 2. 復元できる表形式で書き出す

1世代につき、指定したスプレッドシート内に1つの新しいタブを作る。名前は`請求管理ツール_バックアップ_YYYYMMDDHHMM`とし、日時はバックアップ開始時点の日本時間を使う。例えば`請求管理ツール_バックアップ_202611031230`。以前の世代と元からあるタブを上書きしない。同じ分に別の処理のタブがある場合は上書きせず、次の分での実行を案内する。同じ処理ID・同じ内容の通信再試行に限り、自分の未完了タブを継続する。

1行目は「種別・バックアップID・対象・順序・分割番号・分割数・データ・状態」の8列の見出し。2行目はMANIFESTとして形式版1・DB版9・保存日時・全表の件数・SHA-256照合値とWRITING／COMPLETEを持つ。3行目以降のPAYLOADへ、項目定義と全表・全列の値を含むJSONを、1セル12,000 UTF-16コード単位以内で絵文字を分断せず分割する。

INTEGER列は10進文字列、TEXT列は元の文字列、NULLはJSONのnullとして保持し、列定義で復元時の型を決める。SQLiteの64ビット整数をJavaScriptの浮動小数へ変換しない。表の行は読み取った順に保持して会社の表示順も再現する。復元先の構造は版管理したマイグレーションから構築し、バックアップに含まれるSQLを実行しない。現在のDBに存在しない将来の設定・テーブルを追加しない。

数値・率・ID・日付は型情報と合わせて保存し、NULL、空文字、0、falseを区別する。JSONは復元可能な文字列にする。数式は使わず、RAW指定で値が自動変換されることを防ぐ。[Google Sheets API ValueInputOption](https://developers.google.com/workspace/sheets/api/reference/rest/v4/ValueInputOption)。

容量・セル長・API制限は実装時に検証し、超過しても切り捨てない。複数呼出しにまたがるため、全体の完了状態を管理する。[Google公式の利用制限](https://developers.google.com/workspace/sheets/api/limits)。

## 3. 書出し手順

1. ローカルの整合したスナップショットを固定する。
2. テーブル別に型と順序を揃え、件数・ハッシュを計算する。
3. 指定したスプレッドシート内に日時付きの新しいタブを作り、WRITINGとして書き出す。既存タブは上書きしない。
4. 全データを読み戻し、件数・ハッシュ・関連を元と照合する。
5. 一致した世代だけCOMPLETEとし、最終成功日時を更新する。

通信断やタイムアウトは成功扱いにしない。同じバックアップIDで状態を照合し、再試行で行を重複させない。失敗しても元のローカルデータと以前の正常世代を保持する。ハッシュは偶発的な破損検知用であり、真正性の保証とは分ける。

## 4. 復元手順

1. 利用者が指定したスプレッドシート内のバックアップタブから世代を選ぶ。
2. COMPLETEと対応する形式版を確認する。
3. 数式の混入、欠落、重複ID、型、NULL、分割データ、件数、ハッシュを検証する。
4. 同じIDで一時DBを構築し、外部キー、会社と対象月の一致、明細重複、金額・チェック・集計の一致を確認する。
5. 復元内容と対象日時を表示し、利用者が復元を実行する。確認結果は10分間・1回だけ有効とし、確認後にDBが変更された場合は拒否する。
6. 現在DBを端末内のrestore-backupsへ退避し、全件一致を確認してから、同じ接続上のトランザクションで全件を入れ替える。コミット前に復元後の全表全列・順序を照合し、不一致や制約違反・DBエラーは全件ロールバックする。復元操作の世代を端末内へ先に保存し、再起動後も旧画面からの保存要求を世代検証で拒否して再読込を案内する。復元が失敗してDBを保持した場合も、この確認のため旧画面では再読込が必要になることがある。

元の保存金額を保持し、現在のマスタで過去の金額を再計算しない。初期版は全件復元で、差分マージや手編集されたバックアップの取込は扱わない。必要な認証設定は復元後に設定し直す。

## 5. 受入条件と保留事項

実装時点の全業務テーブルと存在する設定を新DBへ復元し、ID・関連・値・チェック・集計が一致すること。小数、改行、先頭の「=」、NULL等の意味が変わらないこと。未完了世代・欠落・改変を検出し、復元失敗時も元DBが使えることを検証する。

手動実行・Googleログイン（OAuth）・同名時の拒否は合意済み。自動実行・頻度・世代数・削除方針は未決定で、追加していない。OAuthクライアントと設定JSONは、ユーザーの操作時承認を得て作成・保存済み。Sheets・Drive・Picker APIの有効化と本人のテストユーザー登録を確認した。架空DB専用アプリで本人の認可と指定ファイルの選択が成立し、実APIで保存・読戻し・別DB復元の全件一致、既存2タブの保持、再起動相当の接続読込み・トークン更新、未選択ファイルへのアクセス拒否を確認した。画面から変更済みの架空DBを退避・復元し、全件一致・退避保持・選択先差替えの403拒否・旧画面からの保存の409拒否も確認した。本番ユーザーレビュー・他PC実機での検証は未完了。

## 6. Google連携の初期設定

各PCでアプリとDBを個別に稼働させる。提供者が用意する共通のGoogle Cloudプロジェクトとデスクトップ用OAuthクライアントを使い、利用者ごとのプロジェクト作成やIAM権限付与は不要とする。各端末で共通の設定JSONを読み込み、その端末の利用者本人の個人Googleアカウントで認可する。DBと本人のトークンは端末ごとに保持し、共有・自動同期しない。設定JSONは提供者から別途受け取り、他PCへの導入は初期セットアップ資料に従う。認可先のファイルには、ログインした本人の編集権限が必要となる。

Google CloudプロジェクトはAPI・OAuth設定の管理単位、OAuthクライアントはアプリの識別情報、個人Googleアカウントはデータへの操作権限の主体として扱う。プロジェクトの所有者であることだけで、他の利用者のスプレッドシートを読めるようにはならない。要求スコープはdrive.fileだけとし、Google Pickerで本人が選んだファイルへの認可を使う。同じアプリへ過去に本人が許可したファイルもGoogle側の認可対象になりうるため、アプリでは現在の選択先1ファイルだけに限定する。1タブへの認可制限ではなく、専用タブだけを操作する制限はアプリで行う。[Google OAuthの説明](https://developers.google.com/identity/protocols/oauth2/)、[Sheetsスコープ](https://developers.google.com/workspace/sheets/api/scopes)。

設定状況：通常利用のアプリへは本人の明示承認後に共通クライアント設定だけを読み込み、DBの全件一致を確認した。テスト用の個人トークン・選択先は移しておらず、通常利用側のGoogle接続は未実施。ユーザー指定によりプロジェクトを作り直し、旧プロジェクトは利用リソース・認証情報・課金先がないことを確認して削除保留とした。新プロジェクトのアプリ情報は本人の同意確認後に作成した。OAuthクライアントと設定JSONは、ユーザーの操作時承認を得て作成・保存済み。Sheets・Drive・Picker APIの有効化と本人のテストユーザー登録を確認した。架空DB専用アプリで本人の認可と指定ファイルの選択が成立し、実APIで保存・読戻し・別DB復元の全件一致、既存2タブの保持、再起動相当の接続読込み・トークン更新、未選択ファイルへのアクセス拒否を確認した。画面から変更済みの架空DBを退避・復元し、全件一致・退避保持・選択先差替えの403拒否・旧画面からの保存の409拒否も確認した。本番ユーザーレビュー・他PC実機での検証は未完了。

提供者がGoogle CloudでSheets API・Google Picker API・Drive APIを有効にし、Google Auth Platformのアプリ表示名を`Invoice Tool Backup`として「デスクトップ アプリ」のOAuthクライアントを作成する。外部・テスト公開中は、利用する本人をテストユーザーに追加する。ポリシーへの同意やGoogleのデータアクセス許可は本人が確認する。

アプリのバックアップ画面から設定JSONを読み込み、「Googleで保存先を選ぶ」で本人の認証と単一ファイルの選択を行う。drive.fileだけを要求し、include_granted_scopes=false・prompt=consent・trigger_onepick=true・allow_multiple=falseとスプレッドシートのMIME種別を指定する。PKCE・10分間の状態値・1回限りのコールバック検証を使い、返り先は同じアプリの月次・年間画面に制限する。トークン情報のscope・aud、選択されたIDが1つであること、Drive APIが返す実ファイルの種類と本人の編集権限を確認してから保存する。URL手入力はなく、保存・一覧・読取・復元で選択先と接続の世代を検証する。数式の混入・権限不足・対応外版を拒否する。

OAuthクライアント設定・トークン・保存先と最終成功の情報・復元操作の世代は、DBと同じディレクトリ内のgoogle-backupへ保持する。ディレクトリは700、ファイルは600で所有者だけにアクセスを許可し、認証情報はGit・バックアップ・API応答・ログへ含めない。再認証時は新しい認証結果を保存し、期限切れや失敗では再接続を案内する。接続設定ファイルが破損しても月次画面の起動を妨げず、設定し直せる。具体的なURLや認証情報はこの資料へ記載しない。


接続状態はtokens.jsonの形式版2として、drive.fileの確認済みスコープ・本人のトークン・選択ファイルのIDと名前・接続の世代を一緒に保存する。保存は一時ファイルからの置換で行い、旧方式のトークンや選択情報がない接続は再利用しない。トークン更新・再起動後の初回通信でもGoogleのトークン情報から許可範囲とアプリを検証する。取消・選択失敗では以前の接続先を保持する。以前Google側へ許可した広い権限が残り、狭い認可を確認できない場合は、本人がGoogleアカウントで以前のアプリ連携を解除してから再接続する。自動取消しは行わない。[Google公式のデスクトップ向けPicker](https://developers.google.com/workspace/drive/picker/guides/desktop-mobile-picker)。


## 7. バックアップ初回利用時の設定

要求仕様書§24.2・S20-T17〜T19を参照する。通常業務はGoogle設定なしで利用でき、バックアップを初めて使う時にツール上で提供者の設定JSONを読み込む。設定JSONは提供者から利用者へ渡す。設定の配置と読込みを既存の画面が行い、通常は次回以降の再読込みを求めない。クライアント設定の破損時の再読込みと、本人の認可失効時のGoogle再接続は区別する。設定JSONとトークンは端末内のGit対象外ファイルで保持し、請求DB・Googleバックアップへ含めない。配布・起動はGit clone後の手動またはAI Agentによるセットアップを前提とする。トークンのDB格納・OS保護保存は今回追加しない。
