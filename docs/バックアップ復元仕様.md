# スプレッドシートへのバックアップと復元

版：0.5 S18・S25の対象外化と現行DB参照を反映　更新日：2026年11月2日

本書は未実装のS20の補助設計案。現行にGoogleへの書出し・復元機能はなく、保存先・認証・実行方法等は着手前に確認する。要求の正本は[要求仕様書](要求仕様書.md)§18、状態は[仕様管理](仕様管理.md)。

日常の正本はローカルDBとし、管理データを専用Googleスプレッドシートへ書き出し、そこから復元する。既存の参考スプレッドシートは編集しない。

## 0. 実データで使い始める前に完成させる

MVP 1の画面レビューは架空データで行う。MVPの段階に関係なく、実データの利用開始前にバックアップと復元の実装・検証を完了する。

現行の物理DBは版9の5表・46列で、会社・年月ごとの表示設定も含む。構造の正本は[ER図とデータ設計](ER図とデータ設計.md)。将来の論理案は未実装部分を含む。途中段階では、その時点で実装済みの業務テーブル・項目と設定をすべて保存・復元し、スキーマ版と対象一覧を明示する。未実装テーブルをバックアップのためだけに作らない。後続段階でデータ構造が増えたら、書出し・復元・移行と検証も同じ変更で更新する。

## 1. 対象データ

S20着手時点の[現行DB](ER図とデータ設計.md)に存在する全表・全列を対象とする。以下は将来範囲を含む一覧で、未実装の表・項目・設定をバックアップのためだけに追加しない。

| 対象 | 保存する内容 |
|---|---|
| 取引先・月別表示 | ID、名称、会社・年月ごとの表示設定（S31）。メモ・表示順は採用・実装後に含める。S18の長期未取引先の判定・全期間共通の非表示は対象外 |
| 報酬条件 | 単価、税込／税抜、値引き・源泉条件、適用期間 |
| 請求対象 | 内容、小数時間、対象年月、単価、金額、条件と切替前の値。S25の日別稼働・分入力は対象外 |
| 月次請求・請求明細 | 会社×月、明細の源泉有無、合計、MFで計算した源泉の手入力額、請求済・入金済・MF消し込み済 |
| 国保・年金 | 種類、対象年月、支払額、メモ |
| 業務設定 | 復元に必要な設定と形式の版 |

添付・PDF・ファイル参照・添付情報・操作履歴台帳は扱わない。認証情報、トークン、端末固有のパス等は保存しない。

## 2. 復元できる表形式で書き出す

設計案は1世代につき1つの専用スプレッドシート。以前の正常世代を上書きせずに作成する。

| タブ | 内容 |
|---|---|
| manifest | バックアップID、日時、アプリ・形式・DBの版、テーブル一覧、件数、ハッシュ、完了状態 |
| schema | 列、型、順序、NULL表現、長文の分割方法 |
| テーブル別タブ | 実装時点で存在する全業務テーブルのレコード。IDと関連を保持 |
| settings | 業務設定 |
| chunks | 長いJSON・メモの分割データと復元順序 |

数値・率・ID・日付は型情報と合わせて保存し、NULL、空文字、0、falseを区別する。JSONは復元可能な文字列にする。数式は使わず、RAW指定で値が自動変換されることを防ぐ。[Google Sheets API ValueInputOption](https://developers.google.com/workspace/sheets/api/reference/rest/v4/ValueInputOption)。

容量・セル長・API制限は実装時に検証し、超過しても切り捨てない。複数呼出しにまたがるため、全体の完了状態を管理する。[Google公式の利用制限](https://developers.google.com/workspace/sheets/api/limits)。

## 3. 書出し手順

1. ローカルの整合したスナップショットを固定する。
2. テーブル別に型と順序を揃え、件数・ハッシュを計算する。
3. 新しい専用スプレッドシートを作り、WRITINGとして書き出す。
4. 全データを読み戻し、件数・ハッシュ・関連を元と照合する。
5. 一致した世代だけCOMPLETEとし、最終成功日時を更新する。

通信断やタイムアウトは成功扱いにしない。同じバックアップIDで状態を照合し、再試行で行を重複させない。失敗しても元のローカルデータと以前の正常世代を保持する。ハッシュは偶発的な破損検知用であり、真正性の保証とは分ける。

## 4. 復元手順

1. 利用者が専用スプレッドシートの世代を選ぶ。
2. COMPLETEと対応する形式版を確認する。
3. 数式の混入、欠落、重複ID、型、NULL、分割データ、件数、ハッシュを検証する。
4. 同じIDで一時DBを構築し、外部キー、会社と対象月の一致、明細重複、金額・チェック・集計の一致を確認する。
5. 復元内容と対象日時を表示し、利用者が復元を実行する。
6. 現在DBを退避して切り替える。失敗時は元DBへ戻す。

元の保存金額を保持し、現在のマスタで過去の金額を再計算しない。初期版は全件復元で、差分マージや手編集されたバックアップの取込は扱わない。必要な認証設定は復元後に設定し直す。

## 5. 受入条件と保留事項

実装時点の全業務テーブルと存在する設定を新DBへ復元し、ID・関連・値・チェック・集計が一致すること。小数、改行、先頭の「=」、NULL等の意味が変わらないこと。未完了世代・欠落・改変を検出し、復元失敗時も元DBが使えることを検証する。

保存先、認証手順、手動か自動か、頻度・世代数は未決定。今回の作業ではGoogle上の作成・書込・復元は行っていない。
