# 初期セットアップ：Agentに導入を依頼する

更新日：2026年11月15日。対象は、このPCでファイル操作・コマンド実行ができるAI Agentを使う利用者です。配布する公開版の`main`ブランチを導入します。手動コマンドは[手動用の手順](初期セットアップ_手動.md)を参照してください。

初回は1〜3を進め、完了報告を4の基準で確認してください。既存の導入を再開・更新するときは5を使います。OS別の実機検証状況と、認証の用語・対処法は手動用の資料にまとめています。

## 1. 提供者からJSONを受け取り、保存先を決める

バックアップを使う場合は、ツールの提供者からGoogle連携の設定JSONを別途受け取ってください。AgentはGitから取得できず、クライアントIDだけでは生成できません。JSONの内容をチャットへ貼り付ける必要もありません。

利用者が用意するものは、自分のGoogleアカウントと自分が編集できるバックアップ専用スプレッドシートです。テスト公開中は提供者にそのGoogleアカウントのテストユーザー登録を依頼します。Cloudプロジェクトを利用者ごとに作る必要はありません。

Agentは導入・ビルド・起動確認を担当し、Googleログイン、アクセス許可、ファイルの選択は利用者本人が行います。設定JSONがまだなくても、通常業務の起動確認までは進められます。

## 2. 次の依頼文をAgentへ渡す

既存のソースフォルダがあれば、Agentでそのフォルダを開いてから依頼してください。未取得なら、保存したい親フォルダをAgentで開き、以下を渡します。

```text
請求管理ツールの初期セットアップをこのPCで行ってください。
リポジトリ： https://github.com/Takashi-Fujie/Invoice_management_tool.git
導入ブランチ：main
手順：docs/初期セットアップ_手動.md と docs/初期セットアップ_Agent.md

1. OS、現在のフォルダ、既存clone、Gitの状態、Git・Node.js・npmの有無を確認する。
   取得済みならAGENTS.mdと関連資料を読む。未取得なら空の新規フォルダへcloneして読む。
   既存ファイル・未コミット変更・DB・Google設定を上書きしない。
   別ブランチや別の導入があれば、切替・データ移動の前に状況を報告する。
2. Node.jsはpackage.jsonの条件である24以上を使う。
   Gitや対応Node.jsがなければ、OSに合う公式の導入方法を案内する。
   ソフトの導入に管理者権限が必要な場合は利用者の操作を求める。
   Windowsでnpm.ps1が拒否されたらnpm.cmdを使い、実行ポリシーを変更しない。
3. ソースフォルダでnpm ci、npm run buildを実行し、結果を確認する。
   失敗時に依存版や業務コードを独断で変更せず、原因を報告する。
4. PORTは既定8787、DBは既定.local-data/invoice.sqliteとしてnpm startで起動する。
   INVOICE_DB_PATHやPORTが既に設定されていれば、使う保存先とURLを先に確認する。
   127.0.0.1だけで待受け、開いたURL、DBの絶対パス、停止・再起動方法を伝える。
   ポートが使用中なら用途不明のプロセスを停止しない。
   Agentの実行終了でサーバーも止まる場合は、継続起動できるターミナルでの手順を案内する。
5. ブラウザで月次・年間画面が開き、初回DBが空であることを確認する。
   既存DBがある場合は内容をログ出力せず、初回扱いや初期化をしない。
   .local-data、DB、設定JSON、認可情報がGit対象外か確認する。
6. Google設定はバックアップを初めて使うときだけ行う。
   提供者のJSONをツール上の「Google接続の初期設定・変更」で本人に選んでもらう。
   JSONを表示・ログ出力・チャット転載・Git追加しない。本人のトークンを他PCから移さない。
   Googleログイン・アクセス許可・保存先選択は本人に画面で行ってもらう。
7. 実データ利用前に、手動用資料7の別ディレクトリ・別DB・別ポートを使い、
   架空データで保存→バックアップ→金額変更→復元→再起動を確認する。
   通常DBとGoogle設定を共有しない検証先を使う。参考の既存管理表は編集しない。
   復元ボタンは対象DB・保存日時・全件置換を利用者が確認してから押してもらう。
   JSONや本人操作が不足する場合は、通常起動まで進め、検証未完了と報告する。
8. 導入フォルダ・ブランチとコミット・実行したコマンドと成否・URL・DB保存先・
   Google接続と検証の完了範囲・未確認事項・次回起動と停止方法を報告する。

今回の依頼は初期導入のみです。機能追加、公開サーバー化、既存データの取込み、
Cloudプロジェクトの新規作成、OAuthクライアントの作り直しは行わないでください。
```

この依頼文は、自動セットアッププログラムではありません。Agentの権限やブラウザ操作の可否に応じ、必要な本人操作を案内してもらいます。

## 3. Google側の操作は自分で確認する

Agentが起動したツールで「バックアップ・復元」を開き、提供者の設定JSONを読み込みます。その後、自分のGoogleアカウントでログインし、アプリ名`Invoice Tool Backup`と要求内容を確認して、バックアップ専用のファイルを選びます。

設定JSONはアプリ共通の識別情報、ログイン後の認可情報は利用者本人の権限です。Agentや他の利用者へ本人の認可情報を配る必要はありません。通常は再起動しても設定を再利用できます。失効した場合は本人がGoogleへ再接続します。

復元は表示したDBの全件を置き換えます。Agentに確認を任せる場合も、検証用DBのURL・保存先・復元日時を見てから実行してください。

## 4. 完了報告で起動とバックアップを分けて確認する

| 確認すること | 完了の目安 |
|---|---|
| 導入 | `main`のコミット、Node.jsの版、`npm ci`とビルドの成功が記録されている |
| 起動 | 月次・年間を開けるURLと、次回の起動・停止方法が分かる |
| データ | DBの絶対パスが分かり、既存データ・設定を保持している |
| Google連携 | 本人が設定JSON読込み・ログイン・保存先選択を終えている |
| 保全検証 | 検証用DBのバックアップ・復元・再起動後の保持を確認している |

「起動成功」だけではGoogle接続・復元確認まで終わったことにはなりません。JSONや本人操作が未完了なら、その項目を残して報告してもらいます。実機確認の結果だけで仕様管理のレビュー待ちを自動的に実装済みへ変更する必要もありません。

## 5. 次回の起動・更新を依頼する

起動だけなら、Agentで同じフォルダを開き、次のように依頼できます。

```text
このフォルダの請求管理ツールを、既存DB・Google設定を保持して起動してください。
既に起動中なら重複起動せずURLを教えてください。
導入のやり直し・clone・DB初期化は不要です。
```

更新するときは、先に本人がバックアップを完了してから依頼します。

```text
バックアップは完了しています。この公開版をmainの最新版へ更新してください。
既存変更と稼働状況を確認し、アプリを停止してからgit pull --ff-only origin main、
npm ci、npm run buildを行い、同じDBで再起動してください。
未コミット変更・履歴の分岐・DB移行エラーがあれば、上書きせず状況を報告してください。
```

手順が止まった場合は、提供者にOS・Node.jsの版・該当手順・秘密情報を除いたエラー文を伝えてください。用語やエラーの確認先は[手動用資料](初期セットアップ_手動.md#9-困ったときはデータを残したまま確認する)です。
