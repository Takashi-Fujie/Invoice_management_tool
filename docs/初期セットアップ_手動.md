# 初期セットアップ：手動で導入する

更新日：2026年11月15日。対象はGitHubで配布する公開版です。WindowsではPowerShell、macOSではターミナルを使います。コマンド操作をAgentに任せる場合は[Agent用の手順](初期セットアップ_Agent.md)を参照してください。

初回は1〜5を順に進めてください。Googleバックアップを使う場合は6〜7も実施します。8以降は再起動・更新・困ったときの参照用です。macOSの開発環境では検証済みですが、配布先のWindows・奥様のPCでの一連の実機確認は未完了です。仕様全体の受入状態は[仕様管理](仕様管理.md)を参照してください。

## 1. 自分のPCに必要なものを用意する

| 用意するもの | 用途 |
|---|---|
| [Git](https://git-scm.com/downloads/) | ソースコードをPCへ取得する |
| [Node.js](https://nodejs.org/en/download) 24以上と付属のnpm | 依存パッケージの導入・ビルド・起動。サポート中のLTS版を選ぶ |
| Webブラウザ | 入力画面とGoogleログインを開く |
| Googleアカウント・バックアップ専用スプレッドシート | Googleバックアップを使うときだけ必要 |
| 提供者から受け取るGoogle連携の設定JSON | バックアップの初回設定で読み込む。Gitには含まれない |

PCごとにDBを持つため、別のPCへ導入しても会社・請求データは自動で移りません。保存フォルダは、ほかの人と共有しない場所を選んでください。

Google CloudプロジェクトとOAuthクライアントは提供者が管理します。利用者がプロジェクトを作る必要はありません。提供者は設定JSONを別途渡し、アプリがテスト公開中なら利用者本人のGoogleアカウントをテストユーザーへ登録します。Google側の準備は[バックアップ復元仕様の初期設定](バックアップ復元仕様.md#6-google連携の初期設定)を参照してください。

## 2. GitとNode.jsの導入を確認する

GitとNode.jsをインストールしたら、ターミナルを開き直して実行します。

```text
git --version
node --version
npm --version
```

Node.jsが`v24`以上で、各コマンドのバージョンが表示されれば次へ進めます。Windowsで`npm.ps1`の実行を拒否された場合は、以降の`npm`を`npm.cmd`へ置き換えてください。PowerShellの実行ポリシーを変更する必要はありません。

## 3. ソースコードを取得する

新しく導入する場合だけ実行します。すでに同じ名前のフォルダがあれば、上書きせず、既存の導入か確認してください。

Windows（PowerShell）：

```powershell
Set-Location $HOME
git clone https://github.com/Takashi-Fujie/Invoice_management_tool.git
Set-Location Invoice_management_tool
```

macOS（ターミナル）：

```sh
cd ~
git clone https://github.com/Takashi-Fujie/Invoice_management_tool.git
cd Invoice_management_tool
```

以降のコマンドは、この`Invoice_management_tool`フォルダ内で実行します。公開版は`main`ブランチを使います。

## 4. パッケージを導入し、画面をビルドする

```sh
npm ci
npm run build
```

どちらもエラーなく終わることを確認します。`npm ci`にはインターネット接続が必要です。依存版は`package-lock.json`に従います。エラー時に`npm audit fix --force`などで依存版を変えず、末尾の対処表を確認してください。

## 5. アプリを起動し、保存先を確認する

```sh
npm start
```

ブラウザで[請求管理ツール](http://127.0.0.1:8787/)を開きます。ブラウザは自動では開きません。起動したターミナルは開いたままにしてください。停止はそのターミナルで`Ctrl+C`です。

初回は空のDBが作られます。通常業務の起動・入力・保存・年間集計にはGoogle設定は不要です。ただし、実データの利用開始前に、7の架空データによるバックアップ・復元確認を済ませてください。

| 保存物 | 既定の場所（取得したフォルダ内） |
|---|---|
| 会社・請求・明細などのDB | `.local-data/invoice.sqlite` |
| Googleクライアント設定・本人の認可情報・保存先 | `.local-data/google-backup/` |
| 復元直前のDB退避 | `.local-data/restore-backups/` |

`.local-data`はGit対象外です。フォルダを削除するとデータと接続設定を失うため、アプリを消すときも先に保全してください。Googleバックアップに認証情報は含まれません。

## 6. 初めてGoogleバックアップを設定する

1. 利用者本人のGoogleアカウントで、バックアップ専用の空スプレッドシートを作ります。既存の業務管理表とは分けてください。
2. ツールの「バックアップ・復元」を開きます。
3. 「Google接続の初期設定・変更」で、提供者から受け取った設定JSONを選びます。
4. 「Googleで保存先を選ぶ」を押し、自分のGoogleアカウントでログインします。
5. アプリ名が`Invoice Tool Backup`であることとアクセス内容を確認し、本人が許可します。警告や要求内容に疑問があれば、許可せず提供者へ確認してください。
6. 自分のバックアップ専用スプレッドシートを1つ選びます。ツールへ戻ったら「Google接続済み」と保存先の名前・リンクを確認します。
7. 月次入力の未保存内容を保存してから「今すぐバックアップ」を押します。「読戻し検証済みのバックアップ」と保存日時・件数が表示されれば成功です。

毎回、保存済みの全会社・全年月を`請求管理ツール_バックアップ_YYYYMMDDHHMM`という新しいタブへ保存します。時刻は日本時間です。同じ分に別のバックアップがあれば、次の分になってから実行します。既存タブと過去のバックアップは上書きしません。自動バックアップはありません。

設定JSONは通常、最初の読込みだけで済みます。Googleログインが失効したときは、設定JSONの再読込みではなくGoogleへの再接続が必要になる場合があります。テスト公開中の外部アプリでは、Googleの条件により更新トークンが7日で失効します。[Google公式の説明](https://developers.google.com/identity/protocols/oauth2#expiration)を参照してください。

Googleへの認可は、本人がアプリで使うファイルを選ぶ`drive.file`です。同じアプリへ過去に許可したファイルもGoogle側の対象になり得ますが、ツールは現在選んだ1ファイルのバックアップタブだけを操作します。タブ単位のGoogle権限ではありません。[Google Pickerの説明](https://developers.google.com/workspace/drive/picker/guides/desktop-mobile-picker)も参照できます。

## 7. 実データを入れる前に、別の検証用DBで復元を試す

通常のアプリを`Ctrl+C`で止め、同じフォルダで以下を実行します。通常DBとGoogle設定を共有しない検証用フォルダを使います。

Windows（PowerShell）：

```powershell
$env:INVOICE_DB_PATH = '.local-data/setup-check/invoice.sqlite'
$env:PORT = '8788'
npm start
```

macOS：

```sh
INVOICE_DB_PATH=.local-data/setup-check/invoice.sqlite PORT=8788 npm start
```

1. [検証用画面](http://127.0.0.1:8788/)を開きます。架空の会社・明細を入力し、「変更を保存」を押します。実データは使いません。
2. 検証用DB側でも6のJSON読込み・自分のGoogleログインを行い、検証用の専用スプレッドシートを選んでバックアップします。
3. 架空の明細金額を変更し、保存します。
4. 「保存先のバックアップ一覧を読む」から先ほどの保存日時を選び、「復元する内容を確認」を押します。
5. 日時と件数を確認し、「現在のDBを退避して復元する」を押します。復元は、この検証用DBの全件を保存時点へ置き換えます。
6. 変更前の会社・明細・金額へ戻ったことを確認します。アプリを停止・再起動し、復元結果とGoogle接続設定が残っていることも確認します。

確認後は検証用アプリを止めます。Windowsでは次のコマンドで検証用の指定を解除してから、通常アプリを起動します。

```powershell
Remove-Item Env:INVOICE_DB_PATH
Remove-Item Env:PORT
npm start
```

macOSでは通常の`npm start`で既定のDBへ戻ります。検証用のデータ・接続先を通常DBへコピーする必要はありません。Google設定はDBを置いたディレクトリごとに保存されます。

## 8. 翌日以降は、同じフォルダで起動する

```sh
cd Invoice_management_tool
npm start
```

`cd`は親フォルダにいる場合の例です。導入済みのフォルダへ移動してから起動してください。毎回のclone・`npm ci`・JSON読込みは不要です。

ソースを更新するときは、先にGoogleバックアップを完了し、アプリを停止してから行います。未コミット変更がある場合やローカルDBの移行に失敗した場合は、そのまま上書きせず提供者へ確認します。

```sh
git status --short
git pull --ff-only origin main
npm ci
npm run build
npm start
```

## 9. 困ったときは、データを残したまま確認する

| 症状 | 確認・対処 |
|---|---|
| `git`・`node`・`npm`が見つからない | インストール後にターミナルを開き直す。`node --version`が24以上か確認する |
| PowerShellで`npm.ps1`が拒否される | `npm.cmd ci`、`npm.cmd run build`、`npm.cmd start`を使う |
| `EADDRINUSE`で起動できない | 既に起動した自分のアプリを確認する。用途不明のプロセスは終了しない。ポート変更は下記の方法を使う |
| ブラウザで開けない | 起動中のターミナルとURLを確認し、`localhost`ではなく`127.0.0.1`を使う |
| Googleがアクセスを拒否する | ログインしたアカウントと、提供者によるテストユーザー登録を確認する |
| 設定JSONを読み込めない | 提供者にデスクトップ用OAuthクライアントのJSONか確認する。中身はチャットやIssueへ貼らない |
| Google接続が切れた | 「Googleで保存先を選ぶ」から本人が再接続する。DBや認証ファイルを先に削除しない |
| バックアップはあるが接続設定がない | 提供者のJSON読込みと本人のGoogleログイン・保存先選択をやり直す。認証情報はバックアップ対象外 |

ポートを変える場合は、Windowsで`$env:PORT = '8788'`の後に`npm start`、macOSで`PORT=8788 npm start`とし、`http://127.0.0.1:8788/`を開きます。Google連携時も同じURLを使ってください。別PCからの接続やインターネットへの公開はこの手順の対象外です。

解決しない場合は、ツールの提供者へOS、Node.jsのバージョン、止まった手順、認証情報・取引情報を除いたエラー文を伝えてください。

## 用語

- **DB**：会社・請求・明細を保存する、PC内のデータベースファイル。
- **ビルド**：ソースコードからブラウザで使う画面を生成する処理。
- **設定JSON**：アプリをGoogleへ識別させる設定ファイル。本人のログイントークンとは別物。
- **OAuth**：本人がGoogleへログインし、このアプリにアクセスを許可する仕組み。
- **Agent**：利用者のPCでファイル確認やコマンド実行を支援するAIツール。
