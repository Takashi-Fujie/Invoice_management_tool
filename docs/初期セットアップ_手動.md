# 初期セットアップ：手動で導入する

更新日：2026年11月22日。対象はGitHubで配布する公開版です。WindowsではPowerShell、macOSではターミナルを使います。コマンド操作をAgentに任せる場合は[Agent用の手順](初期セットアップ_Agent.md)を参照してください。

初回は1〜5を順に進めてください。バックアップの保存先と復元確認は6〜7で行います。8以降は再起動・更新・困ったときの参照用です。macOSの開発環境では検証済みですが、配布先のWindows・奥様のPCでの一連の実機確認は未完了です。仕様全体の受入状態は[仕様管理](仕様管理.md)を参照してください。

## 1. 自分のPCに必要なものを用意する

| 用意するもの | 用途 |
|---|---|
| [Git](https://git-scm.com/downloads/) | ソースコードをPCへ取得する |
| [Node.js](https://nodejs.org/en/download) 24以上と付属のnpm | 依存パッケージの導入・ビルド・起動。サポート中のLTSバージョンを選ぶ |
| Webブラウザ | 入力画面・年間集計・バックアップを開く |
| 保存先フォルダ | バックアップJSONの保存先。Driveへ保存する場合はPC用Google Driveアプリの同期フォルダ |

PCごとにDBを持つため、別のPCへ導入しても会社・請求データは自動で移りません。保存フォルダは、ほかの人と共有しない場所を選んでください。

ツール内のGoogleログイン・設定JSONは不要です。Google Driveを使う場合は、PC用Google Driveアプリに本人がログインし、同期フォルダを用意します。

## 2. GitとNode.jsの導入を確認する

GitとNode.jsをインストールしたら、ターミナルを開き直して実行します。

```text
git --version
node --version
npm --version
```

Node.jsが`v24`以上で、各コマンドのバージョンが表示されれば次へ進めます。Windowsで`npm.ps1`の実行を拒否された場合は、以降の`npm`を`npm.cmd`へ置き換えてください。PowerShellの実行ポリシーを変更する必要はありません。

## 3. ソースコードを取得する

新しく導入する場合だけ実行します。すでに同じ名前のフォルダがあれば、上書きせず、既存の導入か確認してください。

Windows（PowerShell）：

```powershell
Set-Location $HOME
git clone --branch 0.1.0 --single-branch https://github.com/Takashi-Fujie/Invoice_management_tool.git
Set-Location Invoice_management_tool
```

macOS（ターミナル）：

```sh
cd ~
git clone --branch 0.1.0 --single-branch https://github.com/Takashi-Fujie/Invoice_management_tool.git
cd Invoice_management_tool
```

以降のコマンドは、この`Invoice_management_tool`フォルダ内で実行します。この手順では`0.1.0`タグを使います。タグ指定のcloneは履歴の特定位置を開く状態になります。

## 4. パッケージを導入し、画面をビルドする

```sh
npm ci
npm run build
```

どちらもエラーなく終わることを確認します。`npm ci`にはインターネット接続が必要です。依存版は`package-lock.json`に従います。エラー時に`npm audit fix --force`などで依存版を変えず、末尾の対処表を確認してください。

## 5. アプリを起動し、保存先を確認する

```sh
npm start
```

ブラウザで[請求管理ツール](http://127.0.0.1:8787/)を開きます。ブラウザは自動では開きません。起動したターミナルは開いたままにしてください。停止はそのターミナルで`Ctrl+C`です。

初回は空のDBが作られます。通常業務の起動・入力・保存・年間集計にはGoogle設定は不要です。ただし、実データの利用開始前に、7の架空データによるバックアップ・復元確認を済ませてください。

| 保存物 | 既定の場所（取得したフォルダ内） |
|---|---|
| 会社・請求・明細などのDB | `.local-data/invoice.sqlite` |
| Googleクライアント設定・本人の認可情報・保存先 | `.local-data/google-backup/` |
| 復元直前のDB退避 | `.local-data/restore-backups/` |

`.local-data`はGit対象外です。フォルダを削除するとデータと接続設定を失うため、アプリを消すときも先に保全してください。Googleバックアップに認証情報は含まれません。

## 6. バックアップをファイルへ保存する

上部の「バックアップ・復元」から専用画面を開き、「バックアップファイルを保存」を押します。保存先のフォルダを選ぶと、日時付きJSONを保存します。Google Driveへ保存する場合はPCの同期フォルダを選び、同期完了はPCのDriveアプリで確認してください。フォルダ選択に未対応のブラウザではダウンロードされるので、保存後に同期フォルダへ移します。

下段のリストは、このPCのツールが記録した保存日時・保存場所・含まれるデータです。Drive内のファイル一覧ではありません。ファイルの移動・削除や請求データの復元では、保存履歴は変わりません。

## 7. 架空データでバックアップ・復元を確認する

通常アプリを`Ctrl+C`で止め、別ディレクトリ・別DB・別ポートで検証します。既存DBは上書きしません。

Windows：

```powershell
$env:INVOICE_DB_PATH = '.local-data/setup-check/invoice.sqlite'
$env:PORT = '8788'
npm start
```

macOS：

```sh
INVOICE_DB_PATH=.local-data/setup-check/invoice.sqlite PORT=8788 npm start
```

1. `http://127.0.0.1:8788/`で架空の会社・明細・金額を入力し、保存します。
2. バックアップ専用画面で検証用フォルダにJSONを保存します。
3. 架空の金額を変更して保存します。
4. 復元欄で先ほどのJSONを選び、「復元する内容を確認」で日時・件数を確認してから実行します。現在の検証用DBの全件が置き換わります。
5. 元の会社・明細・金額へ戻ったことを確認し、停止・再起動後も保持されることを確認します。保存履歴は復元の前後で保持されます。

終了後は検証アプリを停止します。Windowsでは以下で検証用の環境変数を外してから通常の`npm start`へ戻ります。

```powershell
Remove-Item Env:INVOICE_DB_PATH
Remove-Item Env:PORT
```

macOSでは通常の`npm start`で既定のDBへ戻ります。検証用データやバックアップを通常DBへコピーする必要はありません。

## 8. 翌日以降は、同じフォルダで起動する

```sh
cd Invoice_management_tool
npm start
```

`cd`は親フォルダにいる場合の例です。導入済みのフォルダへ移動してから起動してください。毎回のclone・`npm ci`は不要です。

ソースを更新するときは、先にJSONファイルのバックアップを完了し、アプリを停止してから行います。未コミット変更がある場合やローカルDBの移行に失敗した場合は、そのまま上書きせず提供者へ確認します。

```sh
git status --short
git pull --ff-only origin main
npm ci
npm run build
npm start
```

## 9. 困ったときは、データを残したまま確認する

| 症状 | 確認・対処 |
|---|---|
| `git`・`node`・`npm`が見つからない | インストール後にターミナルを開き直す。`node --version`が24以上か確認する |
| PowerShellで`npm.ps1`が拒否される | `npm.cmd ci`、`npm.cmd run build`、`npm.cmd start`を使う |
| `EADDRINUSE`で起動できない | 既に起動した自分のアプリを確認する。用途不明のプロセスは終了しない。ポート変更は下記の方法を使う |
| ブラウザで開けない | 起動中のターミナルとURLを確認し、`localhost`ではなく`127.0.0.1`を使う |

ポートを変える場合は、Windowsで`$env:PORT = '8788'`の後に`npm start`、macOSで`PORT=8788 npm start`とし、`http://127.0.0.1:8788/`を開きます。別PCからの接続やインターネットへの公開はこの手順の対象外です。

解決しない場合は、ツールの提供者へOS、Node.jsのバージョン、止まった手順、認証情報・取引情報を除いたエラー文を伝えてください。

## 用語

- **DB**：会社・請求・明細を保存する、PC内のデータベースファイル。
- **ビルド**：ソースコードからブラウザで使う画面を生成する処理。
- **Agent**：利用者のPCでファイル確認やコマンド実行を支援するAIツール。
