# DB移行と復元（S08〜S14・S28・S31）

要求・受入条件の正本は[要求仕様書](要求仕様書.md)§10・§11・§13・§15・§3.1のS10/S11/S12/S13・§17.2のS28・§17.3のS14・§21のS31。本書はローカルDBの移行・復旧手順であり、S20のスプレッドシートへのバックアップ機能とは別の内部保全手順。

確認日：2026年11月2日。現行の物理定義は[ER・DB資料](ER図とデータ設計.md)の版9を参照する。

## 移行

現在の版はPRAGMA user_version=9。初回の空DBは001〜009を順に適用する。版1〜8の既存DBは、アプリ起動時に以下を実行する。

1. integrity_check・foreign_key_checkで元DBを検査する。
2. 元DBと同じ場所へVACUUM INTOで整合した退避を作る。名前は版1なら `<元DB>.pre-s08-<UTC日時>-<識別子>.sqlite`、版2なら `<元DB>.pre-s10-<UTC日時>-<識別子>.sqlite`、版3なら `<元DB>.pre-s11-<UTC日時>-<識別子>.sqlite`、版4なら `<元DB>.pre-s12-<UTC日時>-<識別子>.sqlite`、版5なら `<元DB>.pre-s13-<UTC日時>-<識別子>.sqlite`、版6なら `<元DB>.pre-s28-<UTC日時>-<識別子>.sqlite`、版7なら `<元DB>.pre-s14-<UTC日時>-<識別子>.sqlite`、版8なら `<元DB>.pre-s31-<UTC日時>-<識別子>.sqlite`。
3. 退避の整合性と既存表の全行・全列・版の一致を確認する。
4. トランザクション内で未適用分を009まで順に適用する。007はexpenseを、008はadjustmentと調整の負額制約を追加するため請求対象・請求明細を再構築する。009は月別会社表示の空表を追加する。整合性と、移行前の全行・全旧列の一致を再確認して確定する。

退避作成・比較に失敗した場合は変更を開始しない。移行失敗時はロールバックして起動を中止する。退避は自動削除しない。対応外の版、または既存表を持つ無版DBは変更せず起動を中止する。再起動時に版9へ重ねて列追加しない。

## 別DBへの復元

サーバーを停止する。元DB・退避・WAL等は削除・上書きせず保持する。使用する退避ファイルと、存在しない新しい復元先を指定し、プロジェクトのルートで次を実行する。パスは実際のものへ置き換える。

```sh
node --input-type=module -e 'import {restoreSnapshot} from "./server/migrations.mjs"; restoreSnapshot(process.argv[1], process.argv[2]);' '/絶対パス/退避.sqlite' '/絶対パス/復元先.sqlite'
```

restoreSnapshotは退避を読み取り専用で検査し、新規ファイルにだけコピーする。既存ファイルへの上書きは拒否する。復元後に整合性・版・全表の内容が一致することを確認する。検証失敗時はそのDBで運用を再開しない。

復元先を指定して起動する。

```sh
INVOICE_DB_PATH='/絶対パス/復元先.sqlite' npm start
```

版1〜8の退避を現在のコードで開くと、再度退避を作って版9へ移行する。旧コードへ戻す場合は、そのコードに対応する版の復元先を使用する。移行前の退避には移行後の入力は含まれないため、復旧前に停止した現在のDB一式も保持する。

## 旧版からの移行条件

| 追加版 | 変更・旧データの扱い |
|---|---|
| 002・版2 | 報酬タイプ・時間・単価・以前の手入力額。既存は案件単価、時間・単価は空、手入力履歴はNULL |
| 003・版3 | 報酬／交通費の区分。既存は報酬fee |
| 004・版4 | 現在と報酬／交通費の税区分。既存は税込、交通費から初めて報酬へ戻す区分は税抜 |
| 005・版5 | 値引き有無・率。既存はなし、対象月が2026年10月以降2％、以前1.3％ |
| 006・版6 | 源泉チェックと会社・月の手入力額。既存はなし・0円 |
| 007・版7 | kindへ立替経費expenseを追加。表の再構築で全既存列・制約・参照・ID・金額・チェックを保持。既存区分を自動変換しない |
| 009・版9 | client_month_visibilityを空で追加。会社・対象年月の複合主キー、会社参照、年・月・表示0/1の制約を持つ。旧4表は変更せず、旧月の表示は明細・源泉・チェックから読み取り時に判定する |
| 008・版8 | kindへadjustmentを追加。調整だけ負額を許可し、復元用手入力額も符号付きへ拡張。表再構築で全旧列・関係・金額・IDを保持 |

各移行は全旧列・ID・参照・金額・順序・チェックを保持する。新規画面の初期値と移行時の既定値は区別する。通常DBの過去の更新日時・実行記録は仕様管理・設計の決定記録とGit対象外の記録で扱い、操作手順へ履歴を積み重ねない。
