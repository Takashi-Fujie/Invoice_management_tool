# 請求管理ツール

この公開版は2026年11月3日のMVP 3作業ツリーから作成したスナップショット。個人名・参照資料のURL・開発環境の絶対パスを除去し、過去の開発コミットは含めない。DB・実データ・認証情報・依存パッケージ・ビルド結果は同梱しない。公開版のDB設定は`INVOICE_DB_PATH`、既定の保存先は`.local-data/invoice.sqlite`。既存データの自動取込みは行わない。

会社ごとの月次明細をローカルWebで入力し、報酬・交通費・立替経費・税・値引き・源泉と請求済・入金済を管理する。対象年月は全社共通。会社別・全社の当月集計を会社カードの下に表示し、全社分を一括保存する。

## 起動と検証

Node.js 24以上。依存版はpackage-lock.jsonで固定する。初回は`npm ci`、続けて`npm run build`と`npm start`を実行し、[月次入力](http://127.0.0.1:8787/)を開く。停止はCtrl+C。

保存先は`.local-data/invoice.sqlite`（Git対象外）。`INVOICE_DB_PATH`で別DBを指定できる。空DBは001〜009で版9へ構築する。版1〜8の既存DBは退避の検証後に未適用分を移行し、失敗したら元の構造へ戻して起動を止める。通常の画面操作はネット接続を必要としない。

| コマンド | 確認対象 |
|---|---|
| `npm test` | 計算・期間切替・URL復元と履歴移動・DB/API・全社保存・移行と退避復元・月次集計・前月コピー |
| `npm run test:mock` | 補助モックの回帰検証 |
| `npm run build` | TypeScriptの型検査と画面ビルド |
| `npm run format:check` | ソース・テストの整形 |
| `python3 docs/diagrams/build-er-viewer.py` | DB資料からER閲覧HTML・概要図・期間参照図のDOT/SVGを再生成。Graphvizのdotを使う |
| `python3 .agents/skills/sync-spec-db/scripts/check_docs.py` | 実DBを開かず、仕様ID・リンク・DB定義・ER・項目表・閲覧HTMLを照合 |

資料の同期・整合確認には、プロジェクト専用の [仕様・DB資料の同期スキル](.agents/skills/sync-spec-db/SKILL.md)を使う。`$sync-spec-db`で明示的に呼び出せる。判断を含む手順はスキル、常設ルールはAGENTS.mdを参照する。

画面は確認済みモックに基づくが、本番はSQLiteへ保存する。モックは表示中のみの架空データであり、利用開始用の画面ではない。

対象年月は`?year=2026&month=11`で保持する。有効な年月のURLを開くとその月を表示し、指定なし・不正なら端末の当月を使う。画面での月切替は履歴へ追加し、再読み込みやブラウザの戻る・進むでも対象月を復元する。未保存の履歴移動にも保存・破棄・中止の確認を使う。

S27は明細0行の会社に「前月からコピー」を表示し、空の請求前の会社・月へ保存済みの前月報酬を引き継ぐ。明細行があれば説明を含む操作行を非表示にする。交通費・立替経費・月別源泉額・請求と入金のチェックはコピーしない。編集後に通常の全社保存で確定する。[確認済みモック](docs/mockups/multiple-companies.html)の保存は画面内だけで、本番はSQLiteへ保存する。

下端の「変更を保存」はアイコン付きの大きなボタンで、対象年月・全社分の保存状態を示す（S34）。未保存時は保存欄全体の色・記号・太字の案内で強調し、入力不備・保存失敗でも未保存を維持する。保存成功後は通常表示へ戻る。本番画面のユーザーレビュー待ち。

各明細の右端のゴミ箱で1行ずつ削除できる（S30）。削除は「変更を保存」で確定し、請求済・入金済・処理中は操作できない。最後の行を削除すると前月コピー欄が戻る。

当月の会社別集計は請求額0円の会社行を非表示にする（S29）。2026年11月2日に本番画面のユーザーレビュー完了。負額・入力確認の行と全社合計を表示し、非表示会社の内訳も全社合計へ含める。会社カードと保存データは保持する。仕様・受入条件は要求仕様書§16.1、レビュー状況は仕様管理を参照する。

会社の表示・追加（S31）は選択月のモーダルにまとめる。設定のない空月は全社非表示で、入力のある会社は非表示にできない。前月の表示ON/OFFだけをコピーでき、モーダルで反映後に全社保存する。表示設定は明細がなくても保存し、月往復・再読込・再起動で保持する。2026年11月2日に本番画面のユーザーレビュー完了。仕様は要求仕様書§21、状態は仕様管理を参照する。

## 年間集計

2026年11月3日、承認されたS16モックを`mvp/3`専用worktreeへ本番コードとして反映した。MVP 2の現行コードを依存基準に引き継ぎ、元ツリーの未コミット変更を保持している。月次画面の「年間集計」から同じ年を開き、会社別・全社合計の1〜12月と年合計を確認できる。初期表示は請求額と状態アイコン、矢印で金額内訳を開閉し、会社別の月別額から既存入力へ移る。年間請求額が0円の会社行と内訳は隠すが、保存データ・全社内訳への合算は保持する。初期は会社名順で、会社名・各月・年合計の見出しをクリックすると昇順/降順を切り替えられる。全社合計は末尾に固定し、年切替・再読込は会社名順へ戻る。未保存時は保存・破棄・中止を選ぶ。年間専用の読取APIを追加し、DB版9と月次計算は維持する。本番画面はユーザーレビュー待ち。仕様は要求仕様書§22、確認結果は仕様管理S16を参照する。

## 画面デザイン（S35・本番画面レビュー待ち）

承認済みモックの名称・深いグリーンの配色・入力密度・会社管理・下端の保存欄を本番へ反映した。月次カード上部は年間と同じ10内訳と税込金額を表示し、請求額と源泉も項目名を上・金額を下に揃える。値引きは月次・年間とも負号付きで表示し、計算・保存する額を変えない。見出し横で年を直接入力または前後5年から選び、月は左右の矢印で切り替える。保存・未保存確認・URL履歴・請求済ロックと既存のAPI・DB版9は維持する。本番は端末の配色設定に従い、配色の保存機能は持たない。
